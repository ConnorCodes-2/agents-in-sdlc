アプリケーションへの単純な変更でも、複数のファイルを修正してテストを実行する必要がある場合があります。必要なファイルを探して変更し、テストを実行して、問題をデバッグし、変更漏れを見つけて修正する作業を繰り返します。

Copilot のエージェントモードを使うと、IDE 内でより自律的に作業できます。プロジェクトを調べ、必要な変更を複数のファイルに加え、テストを実行して、見つかった問題を自動で修正します。エージェントモードでサイトに機能を追加する方法を見てみましょう。

> [!NOTE]
> 名前は似ていますが、エージェントモードと cloud agent は異なる体験を提供します。エージェントモードは IDE 内で素早くやり取りしながら作業します。Cloud agent は Issue とプルリクエストを介して非同期に作業し、チームの一員のようにやり取りします。

この演習では、次のことを学びます。

- Copilot エージェントモードがプロジェクトを調べ、関連するファイルを特定して連携した変更を行う方法。
- UI とデータレイヤーにまたがる機能を実装する方法。
- Copilot が生成した変更とテストをレビューし、コードベースにマージする前に確認する方法。

## シナリオ

ゲーム一覧が増えてきたため、ユーザーがカテゴリと発行元でゲームを絞り込めるようにします。前の演習で発行元ヘルパーを作成しました。今回は Copilot エージェントモードを使って、残りのデータレイヤー、UI、テストを完成させます。

## Tailspin Toys の Web サイトを実行する

変更を加える前に Tailspin Toys の Web サイトを確認します。サイトは開発者向けテーマのボードゲームクラウドファンディングプラットフォームで、ゲームの一覧と詳細を表示します。単一の Astro アプリがビルド時に静的 HTML を生成します。ページの frontmatter から Drizzle ORM でローカル SQLite データベースを直接参照します。別のバックエンド API やクライアント UI フレームワークはありません。再利用可能なデータアクセスヘルパーは `src/lib/` にあり、インタラクティブ機能は標準 DOM API を使う小さな Astro `<script>` で実装します。

### Web サイトを起動する

`npm run dev` タスクを使って単一の Astro 開発サーバーを起動します。

1. 前の演習で使った `main` ブランチの codespace に戻ります。
2. <kbd>Control</kbd>+<kbd>`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>`</kbd> (Windows/Linux) を押してターミナルを開きます。
3. フィルター作業用ブランチを作成して切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーの起動後、次のような URL が表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` を開くダイアログが表示された場合は、**x** を選んで閉じます。

5. <kbd>Command</kbd> (Mac) または <kbd>Ctrl</kbd> (Windows/Linux) を押しながら、ターミナルに表示された `http://localhost:4321` を選択します。codespace では localhost のリンクが `https://<your-codespace-name>-4321.app.github.dev/` に転送されます。

### Web サイトを確認する

- **ホームページ**: タイトル、画像、説明を含むゲーム一覧を表示します。
- **ゲーム詳細ページ**: ゲームを選択すると、タイトル、説明、発行元、カテゴリなどの情報が表示されます。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 演習を始める前に、codespace に戻って Copilot Chat パネルを開き、**New Chat** を選んで新しい会話を始めます。モードとモデルは演習ごとに異なります。

テンプレートからプロジェクトを作成したときにバックログの Issue も作られています。Copilot に内容を表示してもらいます。

1. Chat ビューのエージェント一覧から **Agent** を選択します。Agent は自律的に計画を立て、複数ファイルを変更し、ターミナルコマンドとツールを実行します。
2. 利用可能なモデルから **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> ワークショップの作成時に Claude Sonnet 4.5 を使ったため、例をそろえる目的でこのモデルを示しています。特定モデルを推奨するものではありません。LLM は確率的に動作するため、異なる提案が出る場合があります。

> [!NOTE]
> Copilot は別の MCP コマンドを使う場合がありますが、同じタスクを完了できます。

3. 次のプロンプトを送ります。

   ```plaintext
   GitHub リポジトリのバックログ項目を表示してください。ユーザーに役立つものから優先順位を付けるのを手伝ってください。
   ```

4. Issue を一覧表示するコマンドを実行するよう求められたら **Continue** を選択します。
5. 生成された Issue の一覧を確認します。

## 指示ファイルを確認する

コードを生成する前に、Copilot にコンテキストを与える `.github/instructions/ui.instructions.md` を確認します。このファイルにはサイトに機能を追加する方法が記載されています。

1. codespace で `.github/instructions/ui.instructions.md` を開きます。
2. アーキテクチャの概要、コンポーネント設計、テスト容易性、アクセシビリティの原則を確認します。
3. Astro、Tailwind CSS、Drizzle など、ファイル種別ごとの指示へのリンクを確認します。

> [!TIP]
> 指示ファイルから他の指示ファイルやプロジェクトのファイルを参照できます。パスは指示ファイルからの相対パスです。指示を再利用し、大きな内容を小さく分割して、Copilot に例を示せます。

## フィルター機能を実装する

フィルター機能を完成させるには、アプリケーションに少なくとも次の変更が必要です。

- データレイヤー (`src/lib/`) の残りのフィルターロジックを追加、調整する。
- フィルターの動作をテストするテストを追加、更新する。
- ゲーム一覧ページにフィルター UI を追加する。

マージする前にテストが成功する必要があります。Copilot エージェントモードに実装を依頼します。

1. 現在の会話を続けるか、**New Chat** を選びます。
2. **Add Context**、**Instructions**、**ui** の順に選び、UI 指示ファイルを追加します。

   ![UI 指示ファイルを選ぶ例](../../../_images/ex3-select-instructions-file.png)

3. Chat のエージェント一覧で **Agent** が選択されていることを確認します。
4. モデルとして **Claude Sonnet 4.5** が選択されていることを確認します。
5. バックログの関連 Issue に基づいて、次のプロンプトを Copilot に送信します。

   ```plaintext
   関連する GitHub Issue の要件に基づき、発行元とカテゴリで絞り込めるようサイトを更新してください。前の演習で作成した発行元ヘルパーを維持し、必要に応じて改善しながら、残りのデータレイヤー、UI、テストを完成させてください。完了する前にすべてのテストが成功することを確認してください。サーバーはすでに実行中なので、起動しないでください。
   ```

6. Copilot がプロジェクトを調べ、データレイヤーのヘルパー、UI、テストを見つけて変更し、テストを実行する様子を確認します。

> [!NOTE]
> Copilot はプロジェクトの調査、変更、テスト実行などを行います。複雑さやコードベースの規模によっては数分かかります。作業中にエディターに **Keep** と **Undo** の操作が表示される場合があります。作業が終わるとすべての変更に対して選択できるようになるため、実行中に操作する必要はありません。

7. Copilot がテストの実行を求めたら **Continue** を選択します。
8. 作業中にテストが失敗することがあります。Copilot はコード生成とテストを繰り返し、エラーがないと判断するまで修正します。
9. 生成されたコードに問題がないか確認します。

> [!CAUTION]
> Copilot や他の AI ツールが生成したコードは、必ずレビューしてください。

10. 実行中のブラウザーに戻り、新しい機能を試します。
11. すべての動作とコードを確認したら、Copilot Chat で **Keep** を選択します。

## まとめと次のステップ

GitHub Copilot エージェントモードで Tailspin Toys に機能を追加しました。

- エージェントモードで UI とデータレイヤー全体に新しい機能を実装しました。
- プロジェクトを調べ、関連ファイルを特定して複数ファイルを変更しました。
- Copilot が作成した変更とテストをレビューしました。

次は [Playwright MCP サーバーで機能をテストし][next-lesson]、プルリクエストを作成します。

### おまけの演習 — ページネーションを実装する

ゲーム一覧が増えてきたらページ分割が必要になります。この演習のスキルを使い、Copilot にページネーションの実装を依頼してみてください。

- 既存の指示ファイルを使うなど、プロジェクトのベストプラクティスに従います。
- ページサイズをユーザーに選ばせるか、固定値にするか検討します。
- 希望する実装に必要なガイダンスをプロンプトに含めます。
- Copilot に変更を依頼し、コンテキストを追加しながら反復します。これは通常の開発フローです。
