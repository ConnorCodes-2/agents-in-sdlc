プロジェクトに小さな機能を追加しましたが、大きな変更にはさらにしっかりしたプロセスが必要です。GitHub Copilot CLI は組織の既存の開発フローに合わせて使えます。このレッスンから、Issue を起点に新しい機能を作成し、コードと動作を検証して、最終的にプロジェクトへマージする一般的なエージェント型開発の流れを学びます。

> [!NOTE]
> 機能開発を通じて、同じ会話とブランチを使います。通常なら作業するファイルの種類ごとにブランチや PR を分けますが、ここでは主要な概念に集中するため、手順を簡略化します。

このレッスンでは、次のことを行います。

- GitHub Issue から Copilot の会話を始めます。
- Plan モードで要件を決めます。
- Autopilot モードで機能を実装します。
- コードをレビューします。
- 転送ブラウザーで機能を手動検証します。

この機能開発では、後のレッスンでリポジトリの指示を更新し、既存の `quality-checks` スキルを調整し、MCP による検証と QA エージェントを追加して、機能の PR を作成します。

## シナリオ

Tailspin Toys のカタログが大きくなり、訪問者がカテゴリと発行元でゲームを絞り込める必要があります。バックログ Issue には機能の説明がありますが、カテゴリの組み合わせ方法など、コーディング前に合意しておきたい詳細もあります。Plan モードで判断事項を解決し、範囲を定めた実装を Autopilot に依頼します。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。ほとんどの開発者は、次のような流れで作業します。

1. 実装内容を説明する Issue から始めます。
2. 作るものの計画を立てます。
3. コードを作成してレビューします。
4. テストを実行して検証します。
5. 新しい機能を手動で確認します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、マージします。

> [!NOTE]
> チームや組織によって具体的な手順は異なりますが、多くはこの流れに沿っています。

標準的な方法を続けることで、AI が生成したコードが要件を満たし、手書きのコードと同じレビューを受けるようにできます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すとモードを切り替えられます。

- **Interactive**: エージェントが変更を提案し、次に進む前に入力を待ちます。
- **Plan**: エージェントがまず計画を作成します。プロジェクトファイルの編集はできません。
- **Autopilot**: エージェントがコードを書き、テストを実行し、タスクが完了するまで自律的に反復します。

まず Plan モードで計画を確認し、その後 Autopilot で実装します。

## Issue から始める

1. Codespace に戻ります。停止中の場合は再起動します。
2. 星評価の PR がマージされていることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルター機能のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての Issue を表示します。
8. 矢印キーで **Allow users to filter games by category and publisher** という Issue を選びます。
9. <kbd>C</kbd> を押して Issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7` (または同様の番号) が表示されます。`#` を使うと、GitHub の Issue やプルリクエストをコンテキストに追加できます。

## フィルター機能を計画する

計画を立てると、Copilot に作業を任せる前に、機能の実装方法やタスクの進め方を決められます。複雑な作業では、少し時間をかけて計画することをお勧めします。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下に **Plan** と表示されていることを確認します。
2. 先ほど追加した Issue の後に、次のプロンプトを入力します。

   ```plaintext
   この機能を実装するための計画を作成してください。
   ```

Copilot はプロジェクトを調べ、適切な実装方法を判断して計画を作成します。

3. フィルターの動作について質問されたら、希望に応じて回答します。正解は一つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して展開します。
5. 計画を確認し、スクロールして全体に目を通します。
6. 判断と異なる部分があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画を確認したら、Autopilot で実装します。Autopilot は、タスクが完了したと判断するまで問題への対応を繰り返します。

1. **Accept plan and build on autopilot (recommended)** または同様の表示の項目を選択します。
2. プロンプトの下に **Autopilot** と表示されていることを確認します。
3. Copilot が計画に沿ってコードを作成し、テストを実行する様子を確認します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があります。先に計画を確認してください。依存関係の不足やポートの競合が報告された場合は、チェックが完了したと判断する前に環境の問題を解決します。

## 実装をレビューして検証する

生成したコードも、他のコードと同様にマージ前にレビューします。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示に **Plan** や **Autopilot** がないことを確認します。
2. `/diff` を入力し、フィルター機能とテストを確認します。
3. Issue と計画で決めた内容に一致するか確認します。
4. レビューが終わったら <kbd>Esc</kbd> を押して差分画面を閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新しい機能を試す

1. Copilot に次のプロンプトを送り、アプリを起動します。

   ```plaintext
   ブラウザーでフィルター機能を試せるようにアプリを起動してください。URL を教えて、サーバーは実行したままにしてください。
   ```

2. Codespaces でポート `4321` が利用可能になったら、**Open in Browser** を選択します。
3. 計画で合意したカテゴリ、発行元、フィルターの組み合わせを試します。
4. リセットと結果がない場合の動作が Issue と計画に一致することを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。

## まとめと次のステップ

会話モードを使い分けて機能を作成、レビューしました。

- GitHub Issue から Copilot の会話を始めました。
- Plan モードで要件を決めました。
- Autopilot モードで機能を実装しました。
- コードをレビューしました。
- 転送ブラウザーで機能を手動検証しました。
