`quality-checks` スキルで自動チェックを実行し、Playwright MCP でブラウザーからフィルター機能を確認しました。次は、それらをカスタムエージェントにまとめ、明確な QA プロセスを定義します。

このレッスンでは、次のことを行います。

- カスタムエージェントが指示、スキル、MCP ツールと連携する仕組みを確認します。
- 再利用できる品質保証プロファイルを作成して確認します。
- QA エージェントを選び、フィルター機能を Issue の要件と照合します。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テストの網羅性、ブラウザーでの動作を一貫して確認したいと考えています。カスタムエージェントで QA プロセスを調整し、再利用可能なレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、目的、指示、利用可能なツールを記述した Markdown プロファイルで定義する、専門化された Copilot です。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

ここまで使ってきたカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を説明し、`quality-checks` スキルは繰り返し実行するチェックをまとめます。Playwright MCP はブラウザーツールを提供します。QA プロファイルは、それらを使って要件を評価し、結果を報告する方法を Copilot に指示します。これらを置き換えたり、別の会話を開始したりするものではありません。

## QA プロファイルを作成する

機能の PR を作成する前に、再利用できる QA プロファイルを Copilot に作成してもらいます。どのチェックを行うかだけでなく、その範囲と制約も定義します。

1. Codespace に戻り、フィルター機能の会話が Interactive モードであることを確認します。
2. 既定のエージェントに次のプロンプトを送信します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタムエージェントを作成してください。機能を Issue と合意済みの要件に照らして確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP を使って動作を検証し、テスト範囲が不十分な場合はテストを追加します。

   各要件を pass、fail、blocked のいずれかで、根拠とともに報告してください。実装コードを変更する前に確認を求めてください。変更をコミットしたり、プルリクエストを作成したりしてはいけません。

   まずプロファイルだけ作成し、内容を確認できるようにしてください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、意図した QA ワークフローと制約が含まれていることを確認します。検証だけを依頼したのに、不完全なエージェントや範囲の広すぎるエージェントが実装を変更するのを防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. frontmatter を読みます。`description` は必須です。`name` は省略できますが、表示名を指定すると識別しやすくなります。
3. 指示を読み、QA が要件から確認を始め、リポジトリの指示に従い、`quality-checks` スキルと Playwright MCP を使うことを確認します。
4. 根拠を報告し、実装コードを変更する前に確認を求め、変更をコミットしたり PR を開いたりしないことを確認します。
5. 必要な役割や制約が抜けている場合は、続行する前に既定のエージェントに修正を依頼します。

## Issue に対して QA を実行する

Copilot CLI は会話を開始するときにプロジェクトのエージェントを読み込みます。プロファイルを作成した後、同じフィルター機能の会話を再開して QA を選びます。会話には Issue と計画の判断がすでに含まれています。

1. 次のプロンプトでエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> 作成直後のため、利用可能なエージェント一覧に表示されない場合があります。その場合も上記のコマンドで有効にできます。

2. QA エージェントに次のプロンプトを送ります。

   ```plaintext
   Issue と計画で合意した内容に照らしてフィルター機能をレビューしてください。PR を作成する準備はできていますか。
   ```

3. QA エージェントが確認を実行します。
4. 完了したらレポートを読みます。

## まとめと次のステップ

再利用できる専門的な役割を追加し、QA の結果を確認しました。

- カスタムエージェントが指示、スキル、MCP ツールと連携する仕組みを確認しました。
- QA カスタムエージェントを作成して確認しました。
- QA エージェントを選択し、計画と Issue に照らして機能をレビューしました。

実装、スキルの更新、QA プロファイル、テスト、検証レポートがそろいました。次は[機能の PR を作成して Agent Merge を使います][next-lesson]。
