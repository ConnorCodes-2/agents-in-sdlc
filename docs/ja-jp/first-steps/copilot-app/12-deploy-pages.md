GitHub Pages にデプロイして、Space Quiz を公開しましょう。Copilot はワークフローの準備とデプロイを案内しますが、変更をレビューし、サイトが公開されたことを確認するのはあなたの役割です。

このレッスンでは、次のことを行います。

- Copilot に GitHub Pages のデプロイを構成してもらいます。
- マージ前にワークフローとプルリクエストをレビューします。
- デプロイの進行状況を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、まだ簡単に試せる状態ではありません。単一ファイルのサイトを GitHub Pages に公開すると、サーバーや実行時依存関係を追加せずに、公開 URL からアクセスできるようになります。

## Copilot にサイトのデプロイを依頼する

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリで GitHub Pages を有効にしてください。必要に応じて Web サイトをビルドし、GitHub Pages にデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリの説明とローカルでの実行方法を追加してください。これらの変更を含むプルリクエストを作成し、必須チェックが通ったらマージしてください。デプロイが成功するまで監視し、公開サイトの最終 URL を報告してください。Pages の有効化やマージの権限がない場合は、私が承認または実行する必要がある内容を正確に説明してください。サイトが公開されるまでは、成功したと報告しないでください。
```

> [!WARNING]
> このプロンプトでは、エージェントにプルリクエストの作成とマージ、リポジトリの Pages 設定の変更を依頼しています。続行する前に、差分、デプロイ権限、GitHub の承認要求を確認してください。

## ワークフローを確認してデプロイを検証する

1. README は、リポジトリにまだ存在しない場合に限り追加されていることを確認します。
2. ワークフローのビルド手順とデプロイ手順を含め、プルリクエストの変更をレビューします。
3. 必須のプルリクエストチェックが成功した後にのみマージします。
4. GitHub Actions のデプロイ実行を確認し、成功するまで待ちます。
5. 報告された URL を開き、Space Quiz が読み込まれることを確認します。

エージェントに Pages の有効化やマージの権限がない場合は、提示された具体的な手順に従ってください。デプロイが成功し、公開サイトが読み込まれるまでは完了とみなさないでください。
