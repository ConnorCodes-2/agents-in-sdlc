在 agent mode 中使用 GitHub Copilot 时，它会自主探索代码库、提出更改、编辑文件并运行命令。由于这些工作会实时在本地计算机上进行，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。可以内联审查每项差异、接受或拒绝单项更改，并通过后续提示调整或扩展任务，全程无需离开编辑器。

本练习中，你将：

- 实时监控无障碍智能体的工作；
- 审查并接受建议的文件编辑；
- 在会话进行期间指导智能体，在高对比度模式旁添加浅色模式切换功能。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍自定义智能体正在实现高对比度模式。工作进行期间，设计团队又提出了一项要求：他们还希望为觉得默认主题太暗的用户添加浅色模式切换功能。无需从头开始新对话，而是指导当前会话扩展工作范围。

## 监控 Copilot 的进度

Copilot Chat 视图会显示智能体执行的每个步骤，包括探索的文件、运行的命令和提出的编辑。每项文件编辑都会在聊天中内联显示差异及 **Keep** / **Undo** 控件。

1. 返回练习 4 中使用的 Copilot Chat 视图。
2. 智能体工作期间，滚动聊天查看每次工具调用。你会看到读取文件、编辑文件和请求运行的终端命令。
3. 智能体提出文件编辑时，差异会以内联方式显示：
    - 选择 **Keep** 接受更改。
    - 选择 **Undo** 撤销更改，让智能体再次尝试。
4. 还可以打开聊天顶部的 **Files changed** 指示器，查看本次会话中智能体修改的全部文件。

> [!NOTE]
> 如果工具调用需要许可（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待智能体完成高对比度模式。完成后会看到总结更改的最终消息。

## 指导智能体添加浅色模式

高对比度模式就绪后，在同一对话中继续添加浅色模式切换功能。由于使用的是同一聊天会话，智能体会保留之前工作的上下文，包括更改过的组件、使用的样式方案和本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得不错！现在在高对比度切换开关旁边添加浅色模式切换。浅色模式应遵循相同模式，通过 local storage 持久保存，并可从 UI 的同一区域访问。用户应能分别启用高对比度模式和浅色模式。
    ```

2. 智能体会从之前的工作继续，探索现有更改并提出添加浅色模式的方案。
3. 与高对比度模式一样，逐项审查新编辑，并使用 **Keep** 或 **Undo**。
4. 如果智能体的实现方向不符合预期（例如试图以不喜欢的方式重构切换 UI），可以使用聊天输入框旁边的 **Stop** 按钮停止它，然后发送说明更清楚的后续消息。

> [!TIP]
> 指导进行中的会话比从头开始更快。可以通过后续提示要求调整（“简化 CSS，使用 CSS 变量而不是重复选择器”）、纠正方向（“不要添加第三个切换开关，将浅色模式整合到现有设置面板”）或扩大范围（“还要为这两个开关添加键盘快捷键”）。

## 审查工作集

提交前快速检查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 查看全部已更改文件。应看到 Astro 组件、样式和相关测试的更新。
3. 打开其中几个已更改文件并检查差异。确认自定义智能体所要求的无障碍模式已经体现在代码中，例如 ARIA 属性、键盘导航、语义化 HTML 和通过 local storage 持久保存设置。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结和下一步

你已使用 Copilot Chat agent mode 监控并指导进行中的会话：逐项审查文件编辑、接受或拒绝更改，并通过后续提示扩展工作范围，同时保留上下文。

本课中，你了解了：

- 实时监控智能体工作；
- 接受和拒绝单项文件编辑；
- 通过后续提示指导进行中的会话。
